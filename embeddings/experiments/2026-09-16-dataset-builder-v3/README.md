# Passage-supervision dataset builder

## Question and criterion
Implement the [training-data quality follow-up](../2026-09-16-training-data-quality/README.md) for [roadmap Step 4](../../STEPS.md). Success: reproducible matched answer/passage files, selected-passage adapters, grouped splits, inspection reports, and training consumption of vetted negatives without false-negative treatment of known positives.

## Setup
- Implementation validation only. Offline artificial fixtures, seed 42; no upstream dataset download or production dataset generation.
- Local Mac, project Python virtualenv. CLI runtime, platform, code revision and builder hash recorded in `smoke_report.json`. A tiny randomly initialized one-layer BERT and local tokenizer validate training integration; this is not E5 quality evaluation.
- Existing adaptation work was present in the trainer, losses, datasets, CLI and tests. Changes extend the current interfaces; no campaign dispatch or existing dataset changes.
- Model/data upstream revisions and GPU hardware: inapplicable to fixture checks. Actual builds require local input hashes or pinned HF file revisions.

## Execution
Status: complete for implementation and offline validation; production data build and retrieval comparisons remain pending.

Implemented `indic_edge_embeddings.data.build_quality_data` with:
- Full-file reservoir sampling and independent random raw-data inspection samples.
- MSMARCO-XI selected Hindi/English passages, loaded MIRACL training schema, Indic-RAG source paragraphs, SWIM, and reviewed normalized records.
- Matched answer/passage arms with identical query exposure and explicit negatives disabled in both.
- Optional train-only Dakshina lexicon spelling augmentation with v2 fallback.
- Connected split groups for source identity, normalized native/English/generated queries, known positive texts and available article groups. Evaluation exclusions propagate to related retained groups.
- Hashed manifests, rejection/review reports, deterministic outputs, and refusal to overwrite an existing build.

Training integration preserves all known positive texts and split-group IDs. Both collators append explicit negative candidates; InfoNCE and the dual objective use multi-positive masks and exclude related-group candidates of unknown relevance.

The raw row was inspected before execution. The fixture checks schema behavior, not linguistic quality. The four excluded legacy tests require the published E5 model; new tests independently run both collators and both training objectives with a tiny local model.

## Interpretation
The code now supports the proposed comparison and source mixture, including actual training use of supplied negatives. Tests establish deterministic behavior, selected-passage use, source/variant isolation, positive masking and finite training/evaluation losses.

Automatic filtering only removes missing/placeholder supervision and exact specified overlaps. Translation meaning and passage relevance still require inspection. The mixed recipe approximates requested proportions through query caps and Romanization probabilities; actual proportions are reported. One positive per query is selected deterministically while the complete positive list is retained for masking. No automatic negative mining or semantic relevance judge is implemented.

## Decision
Keep the historical dataset unchanged. Use the matched configuration for the first production build and inspect its reports before a bounded answer-versus-passage training comparison. Evaluate the broader mixture separately. Do not claim improvement from passing implementation tests.
